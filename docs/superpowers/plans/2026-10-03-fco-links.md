# fco.bz Short Links — Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking. Spec: `docs/superpowers/specs/2026-10-03-fco-links-design.md`.

**Goal:** Ship `apps/links`: the `fco-links` Worker that redirects `fco.bz/<slug>`, records click analytics in D1, syncs links from a Google Sheet, and serves a Zero Trust–gated dashboard on `admin.fco.bz`.

**Architecture:** One Worker (`worker/index.ts`) routes by host. `fco.bz` → `redirect.ts` (link from `linkCache.ts`, click recorded by `capture.ts` in `waitUntil`). `admin.fco.bz` → `access.ts` JWT check → `api.ts` for `/api/*`, static SPA assets otherwise. A single every-minute cron (`scheduled.ts`) runs the Sheet sync each minute, the rollup at minute 7, the nightly Sheet summary at 06:30 UTC (01:30 Bogotá) and the weekly R2 export on Mondays 07:00 UTC — one trigger, so it fits the Free plan's cron allowance.

**Tech Stack:** Cloudflare Workers + D1 + Cache API, `jose`, `ua-parser-js` 1.x, Google Sheets REST (service-account JWT signed with WebCrypto), React 19 + Vite 7 + TypeScript strict, hand-written CSS with `@theme` tokens, the same minimal i18n module as `sunfest2027`, Vitest (node + jsdom projects).

## Global Constraints

- **Workers Free limits shape the code:** 10 ms CPU and 50 D1 queries / subrequests per invocation; 5M rows read and 100k rows written per D1 day. So:
  - aggregation runs in SQL (`INSERT … SELECT … GROUP BY … ON CONFLICT DO UPDATE`), never in JS loops over raw rows;
  - rollup is incremental by click id with a cursor — each click is read once per dimension, ever;
  - the redirect path never awaits D1 for logging and survives D1 errors via a stale Cache API snapshot;
  - unique visitors are counted at capture time (`is_first`), so rollups stay additive.
- **Privacy:** never store the raw IP. `visitor_hash` = HMAC-SHA256 keyed by a per-day key derived from `VISITOR_HASH_KEY`.
- **Fail closed:** `/api/*` returns 503 if `ACCESS_AUD`/`ACCESS_TEAM` are unset, 401 without a valid Access JWT. `workers_dev = false`.
- **No secrets in git** (public repo): emails, service-account JSON, OAuth secrets, hash key all come from `.secrets` / `.env.local` / Worker secrets.
- Repo conventions: JSDoc on every export, `tid()`, tests assert i18n keys, es + en parity, ESLint zero warnings (lint-staged runs `--max-warnings 0`).

## Spec deviations (agreed or forced)

- **Backup (coordinator change, 2026-10-03):** no Drive CSV. A service account has no storage quota on a consumer Gmail Drive, and R2 is not enabled on the account. Instead:
  1. `GET /api/export.csv?from=&to=&after=` streams raw clicks paged by id (50k rows per response, `X-Next-After` header for the next page). It accepts an Access user **or service-token** JWT, so a scheduled job elsewhere can pull it.
  2. Optional R2: if a `BACKUP_BUCKET` binding exists, the weekly cron writes `clicks/YYYY-Www.csv.gz`; without it the cron logs and skips. The binding is commented out in `wrangler.toml`.
- **Schema additions:** `clicks.day`, `clicks.hour` (Bogotá), `clicks.human`, `clicks.is_first`; tables `sync_state`, `link_stats`, `backup_state`. `sync_runs` only stores runs that changed something or errored, so it doesn't grow by 1,440 rows a day.
- **Dashboard i18n** uses the same tiny `useTranslation()` module as `sunfest2027` instead of react-i18next (identical API, ~20 KB lighter).
- **D1 in tests** is a `node:sqlite` adapter implementing the D1 subset we use (`prepare/bind/first/all/run/batch`), running the real migrations, instead of Miniflare.
